- **수어통역사 섭외 (2시간 내외)**: 우리가 전문 수어통역사가 아니라서 번역기 정확도를 자체적으로 검증하기 어려움 → 수어를 잘하는 분을 섭외해 직접 테스트하고, 인식 오류가 **프로그램(모델) 문제인지 / 입력된 수어 자체의 문제인지** 구분할 것. → [ML / 추론 파이프라인](#-ml--추론-파이프라인-backendinference-config) 정확도 검증 항목과 연결
- **소켓/서버 구조**: 환자(민원인)가 접수했을 때 상담원(의사) 쪽 화면에 데이터가 보이려면 프론트와 백엔드가 **같은 서버**에 있어야 소켓으로 데이터가 전달됨 — 과거 이 문제 때문에 구조를 바꾼 적이 있었음. 백엔드와 프론트를 함께 호스팅할 수 있는 서버를 구할 수 있는지 검토 필요. → [배포/인프라](#️-배포인프라-vercel--gcp) / [시그널링 서버](#-시그널링-서버-nodejs--socketio-server) 섹션과 동일한 맥락 (✅ 이후 Vercel+GCP 전환으로 1차 해결, 아래 참고)

### 4. 2026-06-23 진행 상황 공유 (개발 회의)

배포 구조를 Railway → **Vercel(프론트) + GCP Compute Engine VM(백엔드) + Cloud Run(소켓서버)** 으로 전환했고, DB도 PostgreSQL → **로컬 SQLite(지점별 운영 가정)** 로 바꿨음. 그 과정에서 나온 논의/이슈:

- **소켓 서버가 1대뿐이라 다대다 매칭이 꼬임**: 민원인 여러 명 + 상담원 1명 구조에서, 담당이 아닌 다른 민원인의 데이터가 상담원 화면에 들어올 수 있음 → 동네(지점)마다 어드민 주소를 따로 만드는 방향으로 해결 시도 중. 구현하다가 **세션이 끊기는 문제**가 발견되어 별도로 봐야 함. → [시그널링 서버](#-시그널링-서버-nodejs--socketio-server) 섹션에 코드 근거와 함께 반영
- **배포 환경**: Vercel + GCP로 전환 완료. 태블릿으로 서비스할 경우 **별도 앱(PWA/네이티브)이 필요한지** 검토 중 — 아직 결정 안 됨
- **인식 버그**: 랜드마크를 못 잡는 현상, "안녕하세요"인데 다른 걸로 인식되는 오인식 현상 → 둘 다 재확인 필요
- **카카오톡 토큰 만료** → 재발급해서 다시 넣어야 함
- **프론트(태블릿 대응)**: 레이아웃/터치 사이즈 정도만 조절하면 될 것으로 보임, 큰 구조 변경은 불필요해 보임
- **모델 정확도 (오경님 공유)**: 모델 자체 80% 이상, AIHub validation 데이터 기준 문장 인식 정확도 약 **92%** → 프론트-백엔드 웹 연동은 끝났으니, 남은 건 **랜드마크 추적 정확도**(손 움직임을 제대로 쫓아가는지)를 잡는 것. 분절(세그멘테이션)이 손이 아래로 내려갔을 때 등 동작 경계에서 제대로 되는지 확인 필요 — 안 되면 "수어 인식 자체"가 안 되는 것으로 봐야 함
  - ⚠️ 기존 문서에 코드 기준으로 정리된 수치(시나리오 서브셋 평균 ~87%, 최저 40%)와 차이가 있음 — AIHub 전체 검증셋 기준인지, 키오스크 시나리오 서브셋 기준인지 테스트 범위가 다른 것으로 보임. 수어통역사 테스트 때 같이 정리 필요
- **수어통역사 섭외 일정**: **다음 주 화요일(2026-06-30)쯤** 섭외 진행 예정 → 섭외 후 **1주 이내**로 실제 동작 촬영 + 웹캠 인식 테스트까지 완료, **이후 2주**는 발견된 문제를 모델/프론트/백엔드에 보완 적용. 전체 남은 기간 약 3주 기준. (상세 체크리스트는 [`docs/2026-06-23_회의록.md`](./2026-06-23_회의록.md) 참고)
