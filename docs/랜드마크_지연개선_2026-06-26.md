# 랜드마크 추적 지연 개선 — 클라이언트 MediaPipe (2026-06-26)

작성: 최영수

---

## 1. 문제

웹캠 시연 시 **랜드마크 오버레이가 손을 못 따라가고 지연**되는 현상.

원인 진단(배포 사이트 실측):

| 지표 | 값 | 의미 |
|---|---|---|
| 영상(CAM) | 58~60 fps | 실시간, 정상 |
| 랜드마크(SEND) | **6 fps** | 영상의 1/10 ← 지연의 정체 |
| 서버 처리 | 89.9 ms | 한 프레임의 절반 이상 |
| 업로드 | 15.6 KB | 프레임 이미지 |

### 근본 원인 — 서버 모드 구조
기본값이 `server` 모드였고, 랜드마크를 **서버(VM)에서 계산**했음:
```
웹캠 → 60ms마다 640x360 JPEG → VM 전송
   → 서버 MediaPipe Holistic(complexity=1, CPU, 락 직렬화) 처리
   → 응답 와야 오버레이 그림
```
즉 오버레이가 **서버 왕복 시간만큼 항상 늦음**. 전송 중복방지 가드 때문에 갱신율 = `1/왕복시간` = SEND fps. 게다가 SEND가 낮으면 모델 추론 빈도도 낮아 **인식 정확도에도 악영향**.

---

## 2. 해결 — 클라이언트 MediaPipe

랜드마크를 **브라우저에서 직접** 뽑아 서버 왕복을 제거. 세 단계로 진행.

### (1) 클라이언트 MediaPipe 구현
- **`web/src/mediapipeClient.ts`**: 스텁(throw만 하던 빈 껍데기) → `@mediapipe/tasks-vision`(PoseLandmarker + HandLandmarker) 실제 구현
  - 서버 Holistic과 **동일한 `{pose:33, left_hand:21, right_hand:21}`** (정규화 [x,y,z]) 형식 출력
  - → 백엔드 `landmarks_payload_to_frame` / 프론트 `drawLandmarks` 수정 없이 그대로 호환
  - GPU(WebGL) 우선, 실패 시 CPU 폴백
  - 손 오탐(얼굴·팔꿈치를 손으로 착각) 감소: Hand confidence 0.5 → **0.6**
- **`web/package.json`**: `@mediapipe/tasks-vision` 의존성 추가

### (2) 폴링 주기 / 기본 모드
- **`web/src/hooks/useSignLanguage.ts`**:
  - 클라 모드는 서버 왕복이 없어 폴링 주기 60ms → **20ms**
  - 기본 모드 fallback `server` → **`client`** (배포 키오스크가 자동으로 클라 모드)

### (3) 그리기/검출을 네트워크 전송과 분리 ⭐ (배포 환경 핵심)
(1)(2)만으론 **로컬은 25fps인데 배포는 15fps**로 떨어졌음. 배포에선 랜드마크 POST가 원격 VM으로 가 **왕복 ~50ms**가 붙는데, 기존 코드가 그 응답을 `await`해서 오버레이 갱신율이 네트워크에 묶였기 때문(서버 처리 자체는 0.2ms인데도).

- **`web/src/hooks/useSignLanguage.ts`**:
  - 검출 직후 **로컬 랜드마크로 오버레이를 즉시 그림** (왕복 대기 없음)
  - in-flight 가드를 그린 직후 해제 → 다음 프레임이 네트워크를 안 기다림
  - 예측 전송은 `clientPostInFlightRef`로 **직렬화**(겹침/순서꼬임 방지), 응답 대기는 비동기
  - `handlePredictionData`는 client 모드에서 echo 랜드마크 재그리기 생략(로컬로 이미 그림 → stale 덮어쓰기 방지)
  - 효과: 오버레이 갱신율이 **네트워크와 무관** → 원격 백엔드에서도 검출 속도(≈12ms) 수준으로 부드러움

### 백엔드
**변경 없음.** `/api/predict_landmarks`가 이미 클라 랜드마크를 받도록 구현돼 있어 그대로 사용.

## 3. 결과 (실측)

| 지표 | 서버 모드 | 클라 모드(로컬) | 클라 모드(배포) |
|---|---|---|---|
| MODE | SERVER MP | CLIENT MP | CLIENT MP |
| 서버 처리 | 89.9 ms | 0.3 ms | 0.2 ms |
| 업로드 | 15.6 KB | 3.6 KB | 2.3 KB |
| SEND fps | 6 | 25 | 15 → **30~40 (분리 후)** |
| 손 추적 | 못 따라옴 | 실시간 | 실시간 |

- **로컬(localhost 왕복 ~5ms)**: 6 → 25fps
- **배포(원격 VM 왕복 ~50ms)**: 분리 전 15fps → **분리 후 검출 속도(≈12ms) 수준**으로 회복
- 인식 정확도: 서버 모드와 동등 이상 (클라 4/5 vs 서버 3/5) — **클라 전환이 정확도를 깎지 않음**
- 손 오탐: confidence 0.6 적용 후 **감소**

## 4. 사용 / 설정

### 모드 전환
| 방법 | 효과 |
|---|---|
| 기본값 | **client** (자동) |
| URL `?mp=client` / `?mp=server` | 명시적 전환 (localStorage에 저장됨) |
| 콘솔 `localStorage.setItem('sign-lang-mediapipe-mode','client')` | 직접 설정 후 새로고침 |

> 예전에 테스트한 기기는 localStorage에 'server'가 저장돼 있을 수 있음 → `localStorage.removeItem('sign-lang-mediapipe-mode')`로 초기화하면 기본값(client) 적용.

### 동작 조건 (클라 모드)
- 키오스크 기기에 **WebGL(GPU)** 필요 (대부분 노트북·태블릿 OK)
- 첫 실행 시 **모델을 CDN에서 다운로드**(~1-3초, 인터넷 필요)

### FPS 뱃지 (영상 우측)
- `MODE`: CLIENT MP / SERVER MP
- `CLIENT`: 브라우저 MediaPipe 처리 시간(ms)
- `SERVER`: 서버 처리 시간(ms)
- `SEND`: 랜드마크 갱신 fps

## 5. 남은 이슈 (이번 작업과 별개)

- **수어 인식 정확도(~70%)**: 클라/서버 무관한 *모델 기본 수준*. 혼동쌍(예: 안녕하세요↔헛수고) 존재.
  - 대처: 수어통역사 테스트 때 ① 데모 수어 고정 세트 + 인식률 측정 ② 시나리오 모드로 후보 좁히기 ③ 상담원 "인식 수정" 버튼으로 즉석 교정
- **튜닝 여지**: 더 부드럽게 원하면 Pose 모델 full→lite (정확도 트레이드오프). 현재는 정확도 우선으로 **full 유지**.
